# 旧检索索引的保留数据迁移

此工具将同一数据库内的 `search_documents` 异步向量索引迁移为同步索引。仓库登记、revision、源码事实、模块产物和 embedding 缓存不迁移；检索文档与向量直接在数据库内复制，不重新调用解析器或模型。

## 执行范围

脚本为 `scripts/migrate-seekdb-vector-index.ts`。默认仅显示数据库和文档数量，不修改表。应用迁移必须显式提供 `--apply --allow-write-fence`；扩展初始化不会自动执行这种维护操作。

```bash
tsx scripts/migrate-seekdb-vector-index.ts --database forexplore_code_intelligence
tsx scripts/migrate-seekdb-vector-index.ts --database forexplore_code_intelligence --apply --allow-write-fence
```

连接配置读取 `CODE_INTELLIGENCE_SEEKDB_HOST/PORT/USER/PASSWORD`，默认本机 2881 端口、root、空密码；只接受本机端点。保持原数据库配置，维护期间暂停触发新的分析任务。

## 迁移步骤

1. 单独事务持有迁移控制行的排他锁，防止多个维护进程同时迁移。DDL 使用另一连接，避免隐式提交释放互斥锁。
2. 按数据库返回的完整表定义创建临时检索表，仅修改表名和目标向量索引的 `SYNC_MODE`，保留其他列、全文索引及参数。
3. 在原表安装 INSERT、UPDATE、DELETE 三个临时拦截触发器。维护期间读取继续可用，写入明确报错，不会静默丢失。
4. 将全部现有文档和向量复制到临时表，检查行数和同步索引定义，再通过一条 `RENAME TABLE` 原子切换。
5. 原表保留为 `search_documents_backup_<随机后缀>`，具体名称输出到日志。移除本次触发器并释放连接。重新加载扩展后沿用旧库。

新旧检索表同时存在，会增加磁盘占用；容量不足时复制失败，正常错误处理会删除本次临时表并移除拦截触发器，原表保留。脚本没有自动删除备份的步骤。

## 中断恢复

正常 SQL 错误会执行清理；强制退出进程、断电或数据库断连可能留下临时表及拦截触发器。事务互斥锁随数据库连接断开释放，但触发器是持久对象，原表可能继续拒绝写入。

恢复方式是重新运行同一迁移命令。若尚未切换，脚本重新复制原表，先前残留的迁移触发器会随原表进入备份，新检索表可写。若已经切换，同步索引检查使脚本直接返回，不再次复制；残留触发器只附着在备份表上。临时表和备份表需要在核对后手动清理。

备份是迁移时点的数据，不包含切换后的新写入。不能在已有后续写入时直接用备份替换当前表，否则会丢失这部分新数据。回退应用代码不要求删除当前数据库或备份。

## 已验证与限制

`scripts/verify-seekdb-index-migration.ts` 使用独立临时数据库，验证了三类写入拦截、注入复制失败后的原表保留和恢复写入、并发互斥、全部向量和附加 JSON 列保留、原表备份、全文检索、复制后 ANN 及新写入立即可检索。

实测 SeekDB 1.3.0.0 接受 MySQL `GET_LOCK` / `LOCK TABLES`，但未实现预期互斥，不能把成功返回当作保护证据。直接在已有数据上重建向量索引遇到了未结束的 DDL；官方 `dbms_index_manager.refresh()` 在当前实例超时。因此采用显式维护和实测有效的写入拦截。官方异步索引及刷新说明见 [SeekDB 1.3 发布说明](https://github.com/oceanbase/seekdb/releases/tag/v1.3.0)。

截至本说明编写时，真实旧库仅完成只读检查：295,123 条检索文档、2 个仓库、7 份模块产物，未应用迁移。实际维护因临时禁止写入及异常中断残留风险需要单独确认；自动审批此前拒绝了将其直接接入初始化的方案。
