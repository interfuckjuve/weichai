## 判定规则

验收结果只有 passed、failed、blocked、not-run。模拟模型和内存存储测试不能替代真实数据库、模型及产品工作流。缺少 SDK、数据或服务必须记为 blocked，不能以替代语言或静态检查标记通过。所有新算法收益均需实测。

记录运行命令、源码版本、数据版本、模型标识及维度、数据库版本、硬件、并发、缓存状态、耗时和原始结果。日志不包含凭据。保留修改前的测试基线，修改后不允许新增回归。

## G1 模块主流程

- 从产品实际入口选择目标模块和历史仓库，检索、查看证据并选择完整候选模块。
- 结果具有 repository/revision/project/module 身份、完整文件清单及依赖清单；多个符号归并为一个模块，函数仅是证据。
- 覆盖同语言、跨语言、部分覆盖、同名不同职责、无匹配、过期索引、模型超时。
- 选择候选后多文件源码来自同一快照；生成/翻译流程消费模块包，至少三个真实任务通过编译及 Spec 行为测试。未完成生成侧时不得宣称全流程已跑通。

## G2 真实表示与证据

- 主链路可配置真实 embedding，查询和文档模型、维度与指令一致；hash 仅作明确标记的离线基线。
- 模块具备职责、接口、实现依赖多视图；全文保留标识符，代码块可通过模块归属补充候选。
- 各项要求输出支持、部分支持、冲突或未知及有效证据；模型自评分不能冒充经校准概率。
- 无效 ID、过期证据、服务失败及降级可观察，不静默伪造成功结果。

- Java、ArkTS、C/C++、Kotlin/KMP 分别报告文件发现、语法、定义引用、调用及构建配置支持等级。
- 使用可构建的跨文件样例；ArkTS 覆盖 ets 与框架关系，C/C++ 覆盖编译命令，KMP 覆盖 source set 和 expect/actual。
- JNI、Node-API、KMP 绑定和框架回调分别包含有效、歧义、端点缺失及配置不匹配用例。
- 关系具有来源、端点、构建上下文和证据；未知关系不得标为确定。分别报告各桥接类别边精确率、召回率和路径恢复率。
